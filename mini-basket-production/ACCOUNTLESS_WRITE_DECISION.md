# 保護者ログイン不要・×○即時共有（A方式）運用仕様

最終方針：**A方式**（2026-11-17）。保護者アカウント作成なし、Googleログインなし、PINなし。共通URL → 子どもの名前（あいうえお順）→ カレンダー日付タップで回答。送信成功直後にFirebaseのリアルタイム監視で全員の画面に反映する。

## 運用ルール（確定）
1. 月初1日00:00 JSTに翌月分の保護者入力をロックし、3か月先の下書きカレンダーを作成する。下書きは**管理者が公開OKするまで非公開**。
2. ×は自分の担当日、○は他人の担当日への自発的な交代候補として記録する。○の回答は曜日指定に関わらず可能。
3. 元担当者名は保持する。元担当者の×と候補者の○があっても**自動交代しない**。候補者0人の日は強調表示し、管理者が個別調整する。
4. 管理者だけGoogle認証。交代確定・公開・締切変更・中止・実績記録・回答訂正は管理者が行う。実施回数は実際の当番完了後の記録だけで加算する。
5. 2026年12月の確定当番表、既存の2027年1月下書きは開発中に勝手に変更しない。

## なりすましと誤入力：対策と限界
**非常に重要**：名前選択は本人確認ではない。匿名Firebase UIDはブラウザ・端末セッションを区別するだけ。最初の回答がない日なら、別人が他の子ども名を選んで×／○を送信できる。これを防ぐには別の本人確認または招待方式が必要で、今回のA方式では採用しない。この危険はEmulatorで再現済み。

**予防：**
- 共通URLの配布はチームの保護者連絡網のみ。SNSなどに一般公開しない。ただしURLの秘匿は強い認証にはならない
- 選んだ子どもの名前、日付、×／○を送信直前の確認画面に明示。本人か確認してから登録・取消
- 入力種別は「元担当者×」「その他の保護者○」のみに制限。試合・休み・未公開月・締切後・交代確定後の入力をサーバー側で拒否
- 既存の回答は最初に記録した匿名UIDだけが変更・削除可能。別スマホからの変更やブラウザ履歴消去後の修正は管理者へ依頼
- 公開済み当番表と回答だけを保護者へ共有し、学年・不可日・実績台帳・内部監査ログは管理者限定

**早期発見：**
- 登録した×・○は即時に全員のカレンダーに表示。みんなが自分の回答と違う記録を発見できる
- サーバー側Cloud Function候補 `auditBasketParentAnswer` が各回答の登録・変更・削除イベントを管理者専用監査台帳に記録する。削除イベントの「最後に記録したUID」は、削除操作をした人と限らないため、そのように表示しない
- 同じ匿名UIDが複数の子ども名で送信した場合は「確認推奨」フラグ（ただし、きょうだい・端末共有もあり得るため**不正と断定しない**）
- 管理者が `manage-answer-monitor.html` で要確認と直近100件を確認できる。追加の自動通知・メール送信は未実装。監査Functionを本番デプロイしない限り新しい監査記録は発生しない

**訂正・対応：**
- 保護者は回答違いに気づいたら既存のLINE連絡網などで管理者へ申し出る。管理者は本人に直接確認
- 管理者は `manage-parent-answers.html` で回答を訂正・取消し、操作の監査ログを残す
- 交代の正式確定前に候補者本人の了承を確認する。すでに確定済みなら、管理者が交代確定を一度解除してから訂正する
- 不自然な大量入力、連絡不能な誤回答が続いたら、管理者が該当月を一時的に `inputState:'closed'` にして新規書き込みを止め、元回答と履歴を確認して復旧する。締切を緩和する場合も日時を記録する
- 管理者は入力受付中の要確認履歴を原則1日1回確認し、交代確定時は当事者に連絡して再確認する

## 実装状況（本番公開はまだ禁止）
- `parent.html`：回答はFirebase `onSnapshot` で全員に即時反映するクライアント設計。送信前に名前／日付／記号を再確認
- `parent-write-config.mjs`：`ANSWER_PUBLICATION_MODE='instant'` としてAを固定。一方、`PARENT_WRITES_ENABLED=false` は**公開前の安全ゲート**であり、開発中は解除しない
- `firestore-parent-anonymous-write-candidate.rules`：匿名回答の実験用セキュリティルール。許可・拒否テストを実施。ただし名前のなりすましは排除できない
- `firebase.json` は引き続き**閲覧専用ルール**を参照。A選択だけで本番の×・○を開放しない
- `firebase-functions/index.mjs`：月初生成に加えてサーバー監査候補 `auditBasketParentAnswer` を追加。**未デプロイ**、Firebase料金プラン・権限・ログの保持期間の確認が必要
- `manage-answer-monitor.html`：管理者監査画面（未公開）。怪しい回答を「確認推奨」と表示するが本人確認の代替にはならない
- `manage-parent-answers.html`：管理者の回答訂正・取消と監査履歴（開発中）
