# ミニバス当番管理｜本番準備版（作業中）

## 現在できること
- `index.html`: スマホ画面での名前選択、月別のロック状態、×・○入力の試作（**端末内保存**）
- `core.mjs`: 月初の締切判定、仮当番案、自動ファクトチェック、交代候補、7日経過の判定
- `core-tests.mjs`: 15個のルール確認テスト（確認済み）
- `firestore.rules`: **未デプロイ**のFirebaseアクセス制御案

## 必ず区別すること
- 現在のGitHub Pages版は本番ではありません。15人の入力同期、メール送信、実際の月初自動作成は**まだ稼働していません**。
- 本番は **ミニバス専用Firebaseプロジェクト** を使用し、野球の道具アプリのFirebaseやデータを流用しません。
- Firebaseプロジェクト接続後、Cloud Firestore + Authentication（保護者: 匿名サインイン／管理者: Google認証）を構築し、ルールを安全性検証してからデプロイします。
- GitHub PagesのURLは公開されます。「名前を選ぶだけ」は本人確認ではありません。匿名サインインでも他人の名前で登録できるリスクが残ります。保護者が理解したチーム内の簡易運用とし、変更記録・確認画面・管理者監視を併用します。
- 管理者UIDを実値に置換するまで、`firestore.rules` の管理者権限は有効になりません。
- 全員の回答完了、当番不可日、個別曜日条件、1日1人、休み・試合日は当番なし、交代募集中0件が最終確定の前提です。未回答者を希望なしとみなしません。
- 「代われる日○」は交代候補の意思表示です。○の日をすべて本人に割り当てる意味ではありません。
- 新しい月の希望が集まる前の仮当番案は、未確認の希望まで反映できません。公開・確定前に再照合が必要です。

## 12月1日の運用例
- 2027年1月：保護者入力をロックし閲覧のみ
- 2027年2月：保護者の入力可能
- 2027年3月：仮表作成・管理者承認後に公開して入力可能
- 東京時間（JST）を基準とし、締切時刻はクラウド側で検証
- 自動月次作成はサーバー側のスケジュール実行を必要とします。稼働前に費用・権限を確認します。

## 実装の順番
1. ミニバス専用 Firebase プロジェクト作成・接続
2. 実際のメンバーの曜日条件を全員確認・登録し、管理者権限を設定
3. Firestore の参照・書込み・月ロックルールをエミュレーターでテスト
4. 保護者の入力→別のスマホへライブ反映、操作履歴保存
5. 当番自動組み換え、管理者承認、確定後の再照合と版管理
6. 月初スケジューラー、7日経過のメール通知、再通知防止
7. 文字版確認→季節デザイン選択→画像生成→画像ファクトチェック
8. Excelバックアップ・管理者交代マニュアル・15台同時テスト

## 引き継ぎ
当番係はアプリ画面だけ操作。技術管理責任者にはFirebaseプロジェクトとGitHubリポジトリの管理権限を適切に共有し、アカウントのパスワード自体は共有しません。
